## 🎯 The Project (Refresher)

**Name**: Fedora Automation Tool
**Goal**: Generate customized Fedora Linux setup scripts (one `.sh` file, user downloads and runs)
**Cost**: $0/month (GitHub Pages)
**Maintenance**: ~45 min/month (quarterly checks)

**Architecture**:
- **Frontend**: Static HTML5/CSS3/JavaScript (GitHub Pages)
- **Config**: YAML files (source of truth)
- **Build**: Python pipeline (validation + JSON generation)
- **Output**: Downloadable `.sh` script (runs locally)

## 📋 File-by-File Breakdown

### **Python Build Pipeline** (Read SPEC_02)
```
build/
├── build.py (100-150 lines)
│   ├── Load YAML configs
│   ├── Run validators
│   ├── Generate data.json
│   └── Report errors
│
├── validator.py (300-400 lines)
│   ├── Check YAML syntax
│   ├── Validate bash commands
│   ├── Check dependencies
│   └── Verify field types
│
├── generator.py (100-150 lines)
│   └── Convert YAML → JSON
│
└── tests.py (400-500 lines)
    ├── Unit tests for configs
    ├── JSON validation
    └── Bash syntax checks
```

### **Configuration Files** (Read SPEC_01)
```
config/
├── metadata.yaml          (globals, tested versions)
├── dnf.yaml              (package manager tweaks)
├── multimedia.yaml       (audio, video, codecs)
├── development.yaml      (dev tools, languages)
└── tweaks.yaml           (system optimizations)

Each file contains 10-20 items with fields:
  - id (unique identifier)
  - label (user-facing name)
  - command (bash to run)
  - requires_sudo (boolean)
  - tested_fedora (list of versions)
  - depends_on / conflicts_with (relationships)
  - tags, impact, status, etc.
```

### **Frontend** (Read SPEC_03, SPEC_04)
```
web/
├── index.html            (semantic HTML, no frameworks)
├── style.css             (vanilla CSS, responsive, accessible)
├── app.js                (vanilla JS, no dependencies)
└── data.json             (generated by build.py)

No external dependencies. ~2000 lines of code total.
```

### **Deployment** (Read SPEC_05)
```
.github/
└── workflows/
    ├── validate.yml      (GitHub Actions: run tests on push)
    └── deploy.yml        (GitHub Actions: auto-deploy if tests pass)

Settings:
  → GitHub Pages enabled (source: /web)
  → Branch protection on main
  → Actions workflow required to pass
```
